🔥 Reusable Pattern: Safe Drag + Update for Heavy GUIs

Description:
-----------
A design pattern to avoid performance and memory problems when dragging/moving objects in GUI applications (e.g., red lines, sliders, scrubbers). Heavy updates are deferred until the drag/release ends, while lightweight visual feedback is provided during the drag.

Key Principles:
---------------
✅ Motion events do not trigger expensive updates.
✅ Only store the position during dragging (no compute).
✅ Visual feedback during dragging is lightweight (position, color, floating label).
✅ Final computations (heavy redraws, calculations) happen only ON RELEASE.
✅ Rate-limited visual updates to avoid overloading the GUI event loop.
✅ Clean up any floating labels or temporary visuals after dragging ends.

Checklist to Apply:
-------------------
[ ] On drag start → set dragging = True, store start_x.
[ ] On motion → update end_x only.
[ ] If enough time has passed (rate-limit), update visuals only (no compute).
[ ] On release → compute final value, do expensive updates once.
[ ] Clamp values to allowed range if needed.
[ ] Clean up floating labels and reset dragging state.

Use Cases:
----------
✔ EEG viewers → red line, markers.
✔ Audio apps → waveform scrubbers.
✔ Image editors → sliders, lines.
✔ Video editors → timelines, markers.
✔ 3D viewers → draggable handles.

Name:

"Safe Drag + Update for Heavy GUIs Pattern"
