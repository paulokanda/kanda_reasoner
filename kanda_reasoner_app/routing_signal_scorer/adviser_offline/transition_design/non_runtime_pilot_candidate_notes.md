# P8 - Non-Runtime Pilot Candidate Implementation v1

This milestone adds the first static Pilot candidate implementation record.

The record is not a runtime Pilot. It is an inert, immutable metadata structure
that declares identity, boundaries, preconditions, allowed declarations, and
forbidden capabilities for future governed work.

## What P8 adds

- `non_runtime_pilot_candidate.py`
- Static candidate identity metadata.
- Static boundary state metadata.
- Static allowed and forbidden capability declarations.
- Static precondition declarations.
- Fixed no-effect constants.

## What P8 does not add

P8 does not add runtime Pilot behavior, Copilot behavior, route selection, route
execution, route comparison, live validation, input processing, output
generation, prompt loading, prompt-library reading, freeze-memory reading,
gold-set loading, persistence, report writing, queue writing, human decision
recording, approval recording, provider calls, embeddings, vector indexes,
training-data use, batch mode, Limited Shadow Runtime, field-test activation,
definitive enablement, or route authority.

## Activation-gate boundary

The future on/off or maturity activation key is intentionally not implemented in
P8. Any field-test or definitive enablement state belongs to a later governed
Activation Gate Box after lab testing and maturity evidence. P8 records that
field-test and definitive enablement are not allowed in this milestone.

## Match-before-disagree rule

The candidate remains untrusted for disagreement evidence until a later governed
milestone proves reproduction of frozen router/canon outcomes. P8 does not run a
reproduction harness and does not trust disagreement language.
