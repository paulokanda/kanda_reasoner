Error Memory

Keep practical lessons from real project failures so the same mistake is less likely to happen again.

What This Tab Does

In plain English: Error Memory is a project-specific library of lessons learned from errors that actually happened. Each lesson records what went wrong, why it happened, how it was corrected, what must not be repeated, and how the correction should be checked in the future.

The tab does not automatically decide that every error deserves a permanent lesson. You review the evidence and choose whether to save, activate, deprecate, supersede, or delete a lesson.

Before You Start

  1. Confirm the correct Project Root at the top of the tab.
  2. Make sure the error belongs to that project.
  3. Gather the exact error message, useful context, correction, and validation evidence.
  4. Remove passwords, API keys, private credentials, and unnecessary personal information.
  5. Use one lesson for one repeatable failure pattern.
!
Important: Error Memory is prevention guidance. It does not replace inspection of the current source files.

The Safest First-Time Workflow

  1. Put the raw error and useful context in AI-assisted error lesson intake.
  2. Click Check Against Lessons to look for an existing lesson.
  3. Use Copy and Open External AI when you need AI help creating or correcting the lesson.
  4. Paste the formatted result back, or import an approved Error Lesson ZIP.
  5. Review the complete lesson in Error Editor.
  6. Use Correct with AI only for a preview correction.
  7. Use Memorize Error only after the lesson is complete and active-ready.
  8. Confirm the saved lesson appears correctly in the Lessons table.

Project and Folder Controls

Project Root

This is the project whose Error Memory you are viewing. A wrong root can put a lesson in the wrong project library.

Open EM Folder

Opens the current project's durable Error Memory folder.

Open Second Prompt Files

Opens the handoff-output folder used for AI uploads. This is separate from the canonical Error Memory store.

Get path buttons

These buttons copy folder paths. They do not copy lesson content.

Get correct way to send me errors

Copies the canonical instructions for sending an error to AI.

Send Zip Errors

Copies the generalized current-Project prompt for creating one self-contained Error Memory lesson intake ZIP. Lessons are staged for human review and Memorize Error is not executed automatically.

AI-Assisted Error Lesson Intake

This left-side area is a temporary preparation area.

Paste error formatted from AI

Loads a formatted Error Memory JSON block. It does not memorize the lesson automatically.

Copy and Open External AI

Copies the current intake text together with the required Error Memory instructions and opens the selected external Python-coding assistant. Paste manually; the result remains untrusted until reviewed and explicitly memorized.

Clean

Clears the current intake and editor view. It does not automatically delete every disk-backed draft.

Del Draft

Deletes the current matching draft and related pending intake records.

Memorize Error

Saves an active-ready lesson into the canonical Error Memory store. Use it only when the lesson is supported, complete, validated, and free of secrets.

Import Error Lesson ZIP

Loads an AI-created lesson package. Importing is not the same as memorizing.

Check Against Lessons

Searches for possible overlap and helps prevent duplicates.

Copy Error Lesson Intake blueprint

Copies the active-ready template and AI formatting instructions.

Error Editor

The Error Editor is the review area. A selected, imported, or formatted lesson appears here as JSON.

Save

Saves the JSON currently shown in the editor to the canonical lesson store.

Copy and Open External AI

Copies the current editor content with the required AI instructions and opens the selected external Python-coding assistant. The external answer cannot save or memorize a lesson.

Clean

Clears the editor and intake views without approving a lesson.

Undo

Restores the most recently deleted lesson when possible, or reloads the selected lesson.

Delete

Deletes the selected canonical lesson. Use Undo immediately if deletion was accidental.

Transfer Buttons

Export Errors

Creates a portable folder containing valid lessons, including inactive lessons.

Import Errors

Merges unique validated lessons from a KANDA Error Memory export.

Lessons to Clipboard

Copies the complete Error Memory lesson library as JSON to the clipboard for manual AI transfer.

  1. The complete JSON is copied.
  2. A backup JSON file is written.
  3. The same JSON appears in Error Editor as a fallback copy source.
i
This button copies lessons. It does not copy the path to second_prompt_files.

Lesson Status Controls

Mark Draft

Keeps an incomplete lesson without presenting it as active guidance.

Mark Active

Promotes a complete lesson when required fields and validation evidence are present.

Deprecate

Keeps the lesson for history but excludes it from active guidance.

Supersede

Marks the lesson as replaced by a newer lesson.

Correct with AI

Loads an AI correction as preview only. It does not save, activate, delete, supersede, or memorize anything by itself.

Common Mistakes

Memorizing too early

Keep the lesson as a draft while root cause, correction, or evidence remains uncertain.

Creating duplicates

Check existing lessons first. Update or supersede the current owner when appropriate.

Treating Error Memory as source truth

Current source files and current validation remain authoritative.

Copying secrets

Remove credentials and private information before clipboard or AI-transfer actions.

Confusing export with approval

Copying, exporting, importing, or AI-correcting does not approve a lesson.

A Complete First-Time Example

Suppose a validation command used the wrong Python interpreter.

  1. Paste the exact error and interpreter evidence.
  2. Check for an existing interpreter-resolution lesson.
  3. Avoid creating a duplicate when an active lesson already owns the failure.
  4. Prepare one supported lesson if the failure is genuinely new.
  5. Review the JSON.
  6. Keep it as draft until validation passes.
  7. Memorize or mark active only after evidence is correct.

Final Safety Reminder

Error Memory is valuable because it is selective, reviewed, project-specific, and evidence-based. Clear ownership and accurate prevention rules matter more than lesson volume.
