Audit Project

First-time user guide: inspect a project, understand the findings, and move through large-file planning safely without needing programming knowledge.

Start Here: The Safe First Run

i

Best first choice: Architecture Review > Check Update Architecture > Mode: validate.

  1. Open Audit Project.
  2. Select Architecture Review.
  3. Select Check Update Architecture.
  4. Confirm Project root.
  5. Leave Mode on validate.
  6. Keep Require confirm before write selected.
  7. Click Validate Project.
  8. Read Project Audit Results.
  9. Use Copy Audit Results, Copy and Open External AI, or Save Audit Results before asking another person or AI to help. External review is manual and advisory.

What Audit Project Is

Audit Project is the inspection area of KANDA Reasoner. It checks the project before repair work begins. It can identify architecture warnings, study oversized Python files, build a controlled refactor plan, review engineering safety, and inspect workflows.

It does not mean every warning must be fixed. It gives evidence so the next decision is safer.

The Three Main Tabs

Architecture Review

The normal starting point. It contains the general Project Audit and the staged large-file tools.

Engineering Safety

Runs broader engineering, quality, source-hygiene, test-protection, and safety checks. It has its own detailed Help page.

Workflow Review

Checks whether a feature or process has complete steps, correct connections, outputs, and validation. It has its own detailed Help page.

Architecture Review: Four Steps From Audit To WorkBench

  1. Check Update Architecture: inspect the whole project.
  2. Large Module AST Split Audit: study one oversized Python file.
  3. Large File Refactor Planner: create and compare plans.
  4. Large File Refactor WorkBench: generate and validate controlled previews in stages.

1. Check Update Architecture

Validate Project

Use: Runs the selected mode. In validate, it checks the project and reports findings.

Beginner advice: Use this first.

Cancel

Requests cancellation of the running Architecture operation. Use it for a wrong project or a genuinely stuck run. A hard cancellation may stop work mid-run.

Mode: validate, diff, scan, write

validate: inspect and report. diff: preview architecture-artifact changes. scan: print collected project information. write: write architecture artifacts.

Beginner advice: Stay on validate.

Require confirm before write

Adds a human confirmation before write mode. Keep it selected.

Heuristic, Local AI, Web AI

Selects an optional read-only explanation engine after deterministic results exist. Heuristic is local rules; Local AI uses the configured local model; Web AI uses the configured online model after approval.

The deterministic Project Audit remains authoritative.

Clear Audit Results

Clears the visible box only. It does not undo changes or remove saved files.

Save Audit Results

Saves the current report to a file you choose.

Mode Help

Shows a short explanation of the four modes.

Include latest Refactor Report evidence

When selected, copied results can include compact evidence from the latest Refactor Report. Leave it selected for a more complete AI handoff.

Copy Audit Results

Copies the report to the clipboard for an AI conversation, issue, or document.

Copy and Open External AI

Copies a strict read-only audit review prompt and opens the selected external Python-coding assistant. The answer cannot modify Project source or approval state.

Warning Heuristic Resolver

Starts the warning-resolution workflow after warnings exist. It may route work through heuristic, Local AI, or Web AI paths.

Cancel Resolver

Stops the active warning resolver.

Large Module Creation/Refactor Protocol

Copies the governed large-module rules. Paste them with the audit evidence when an AI will create or refactor Python modules.

Project Audit Results

The main read-only output area. It shows progress, issue codes, evidence paths, warnings, and completion status.

2. Large Module AST Split Audit

Use this after the Project Audit names an oversized Python file. It studies structure without refactoring the source.

Target .py

The Python file being studied. Validate Project can populate oversized targets.

Copy Path

Copies the selected target path.

Browse Target...

Lets you choose a Python file inside the active project root.

Large modules count and arrows

Shows how many oversized files were found. The arrows move to the previous or next target.

Run AST Split Audit

Analyzes functions, classes, imports, dependencies, responsibilities, and possible helper groups. It is read-only.

Copy Split Handoff for AI

Copies a structured report for AI review after the AST audit finishes.

Safety classifier: AST heuristic

Explains whether proposed groups appear more or less independent. It is guidance, not permission to refactor.

3. Large File Refactor Planner

The Planner turns one selected large file and its audit evidence into a proposed facade-and-helper plan. It does not change source code.

Settings: Ideal, Max, Min helper

Planning boundaries for module and helper sizes. They do not justify compressed formatting or duplicated code.

Analysis evidence panel

Shows symbols, responsibilities, imports, and dependency evidence.

Proposed split plan panel

Shows the planned facade and helper arrangement.

Analyze File

Builds deterministic evidence from the selected file.

Generate Split Plan

Creates the deterministic refactor plan.

Generate Docstring Plan

Plans documentation changes needed when symbols move.

Review & Refine Plan with Local AI

Creates a separate Local AI review version. It does not silently overwrite the deterministic plan.

AI Refactor Version How To

Explains how deterministic, Local AI, and imported Web AI plan versions differ.

Copy Comprehensive Planning for Web AI

Copies the complete target, evidence, constraints, and plan packet.

Review Imported Web AI Version

Checks a pasted or imported Web AI proposal before it can be adopted.

Show Planning Summary

Shows which planning stages and versions are ready.

4. Large File Refactor WorkBench

The WorkBench is advanced and staged. Buttons unlock in order because each later stage depends on earlier evidence.

Load Latest Planner Plan

Transfers the latest accepted plan into WorkBench ownership.

Recheck Source Hash

Confirms the source file has not changed since planning. A mismatch means the plan is stale.

Analyze Dependency Readiness

Checks whether moved groups and dependencies are sufficiently understood. Read-only.

Generate Real Preview

Creates real facade/helper preview files under governed support storage, not active project source.

Validate Real Preview

Checks structural correctness and migration evidence. Structural pass is not the same as full behavior validation.

Advanced Quality Review and correction rows

Review deeper risks and correct one stage at a time. Rerun the stage after a correction.

Prepare Preflight Backup Readiness

Prepares recovery evidence before any future source authorization.

Build Source Apply Payload

Builds the exact source-ready payload but still does not apply it.

!

Important: Source-payload creation is not authorization. Continue only through the separate completion review and explicit human approval workflow.

Engineering Safety And Workflow Review

Engineering Safety is the broad quality and safety desk. Use its dedicated Help page for full-audit, focused-audit, command, source hygiene, test protection, and other controls.

Workflow Review checks whether a process or feature has complete steps, correct connections, expected artifacts, and validation. Use its dedicated Help page for the detailed controls.

Why Paths And Outside-Project Evidence Matter

Project root identifies the project being audited. Reports, previews, temporary files, and AI exchange packets may be written to governed support or daily-work folders outside active source. This prevents generated evidence from being mistaken for real project code and reduces accidental project contamination.

Safe Versus Advanced Actions

Good first-time actions

  • validate mode
  • Copy or Save Audit Results
  • Run AST Split Audit
  • Analyze File and Generate Split Plan
  • Read-only WorkBench stages in order

Advanced or higher risk

  • write mode
  • resolver actions that propose file changes
  • imported AI versions
  • source payload and later authorization
  • continuing after stale-hash or missing-validation warnings

Common Mistakes

  • Starting in write instead of validate.
  • Clearing results before copying or saving them.
  • Asking an AI to repair warnings without including the audit evidence.
  • Selecting a target outside the active project.
  • Skipping Planner and starting directly in WorkBench.
  • Treating structural validation as proof of unchanged behavior.
  • Assuming an AI review overrules deterministic audit evidence.

Complete Beginner Example

  1. Open Audit Project.
  2. Open Architecture Review and Check Update Architecture.
  3. Confirm Project root.
  4. Run validate.
  5. Copy and save the report.
  6. If a large module is listed, run its AST Split Audit.
  7. Use the Planner only for that chosen file.
  8. Review the deterministic plan before AI versions.
  9. Load the plan into WorkBench only when the source hash is current.
  10. Follow WorkBench stages in order.
  11. Stop before source-writing or authorization unless validation, backup, and human approval are complete.

Authority Boundary

Audit Project diagnoses, explains, plans, and prepares evidence. It does not make every warning mandatory, does not make AI authoritative, and does not automatically grant permission to change or freeze the project.
