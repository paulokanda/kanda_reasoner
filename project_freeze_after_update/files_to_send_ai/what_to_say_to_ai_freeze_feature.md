These rules are mandatory because earlier freeze-entry delivery attempts failed
from avoidable mistakes: stale script-based installers were referenced,
the ZIP was not moved from the drive root into the daily work staging folder,
validation used Bash heredoc syntax in PowerShell, `PYTHONPATH` was not set
before project imports, and validation relied on a non-public result attribute.

### 1. ZIP placement and root-to-staging rule

The user saves/downloads the patch ZIP to the root of the drive where the
target project lives. Do not hardcode `E:\`. Derive the drive from
`<PROJECT_ROOT>`.

Example:

```text
If <PROJECT_ROOT> is E:\kanda_reasoner:
  user saves ZIP as E:\<PATCH_NAME>.zip
  installer moves ZIP to E:\kanda_reasoner_delete_after_daily_work\<PATCH_NAME>.zip

If <PROJECT_ROOT> is D:\client_project:
  user saves ZIP as D:\<PATCH_NAME>.zip
  installer moves ZIP to D:\client_project_delete_after_daily_work\<PATCH_NAME>.zip
```

The install block must first look for the ZIP at the drive root, move the ZIP
into `<drive>:\<project_name>_delete_after_daily_work\`, and install only from
that staging folder.

If the ZIP is not found at either the drive root or the staging folder, the
install block must stop with this exact human-readable error phrase:

```text
zip is not in root of drive:\ where project is
```

Do not tell the user to place the ZIP directly inside the project root.
Do not place installer, README, or temporary scripts in the project root.
Do not use underscore-prefixed patch-name variables, underscore staging folders, or
required installer/validator scripts inside the patch ZIP as the delivery workflow.

### 2. Required install block to give the user

AI must give the user a complete PowerShell install block that follows this
root-to-staging shape:

```powershell
$PROJECT_ROOT = "<PROJECT_ROOT>"
$PATCH_NAME = "<PATCH_NAME>"
$PROJECT_NAME = Split-Path $PROJECT_ROOT -Leaf
$DRIVE_ROOT = [System.IO.Path]::GetPathRoot($PROJECT_ROOT)
$WORK_DIR = Join-Path $DRIVE_ROOT ($PROJECT_NAME + "_delete_after_daily_work")

$ROOT_PATCH_ZIP = Join-Path $DRIVE_ROOT ($PATCH_NAME + ".zip")
$WORK_PATCH_ZIP = Join-Path $WORK_DIR ($PATCH_NAME + ".zip")
$EXTRACT_DIR = Join-Path $WORK_DIR $PATCH_NAME
$BACKUP_DIR = Join-Path $WORK_DIR ("backup_" + $PATCH_NAME + "_" + (Get-Date -Format "yyyyMMdd_HHmmss"))

try {
    Set-Location $PROJECT_ROOT

    if (-not (Test-Path $WORK_DIR)) {
        New-Item -ItemType Directory -Path $WORK_DIR -Force | Out-Null
    }

    if (Test-Path $ROOT_PATCH_ZIP) {
        Move-Item -Path $ROOT_PATCH_ZIP -Destination $WORK_PATCH_ZIP -Force
        Write-Host "Moved patch ZIP from drive root into delete-after-daily-work staging folder:"
        Write-Host $WORK_PATCH_ZIP
    }

    if (-not (Test-Path $WORK_PATCH_ZIP)) {
        throw "zip is not in root of drive:\ where project is"
    }

    if (Test-Path $EXTRACT_DIR) {
        Remove-Item $EXTRACT_DIR -Recurse -Force
    }

    Expand-Archive -Path $WORK_PATCH_ZIP -DestinationPath $EXTRACT_DIR -Force

    # Copy only the intended updated project files from $EXTRACT_DIR to $PROJECT_ROOT.
    # Back up overwritten files under $BACKUP_DIR.

    Write-Host ""
    Write-Host "INSTALL OK: <PATCH_NAME> installed."
    Write-Host "Backup folder:"
    Write-Host $BACKUP_DIR
    Write-Host ""
    Start-Sleep -Seconds 5
    Clear-Host
}
catch {
    Write-Host ""
    Write-Host "INSTALL FAILED:"
    Write-Host $_.Exception.Message
    Write-Host ""
    Read-Host "Press Enter"
    Read-Host "Press Enter again to clear"
    Clear-Host
}
```

The install block must be adapted to the exact files in the patch ZIP. It must
not depend on an installer script inside the ZIP.

### 3. Required validation block to give the user

AI must give the user a separate complete PowerShell validation block that
creates any helper validation `.py` file under
`<drive>:\<project_name>_delete_after_daily_work\`, not inside the project root.

```powershell
$PROJECT_ROOT = "<PROJECT_ROOT>"
$PROJECT_NAME = Split-Path $PROJECT_ROOT -Leaf
$DRIVE_ROOT = [System.IO.Path]::GetPathRoot($PROJECT_ROOT)
$WORK_DIR = Join-Path $DRIVE_ROOT ($PROJECT_NAME + "_delete_after_daily_work")
$VALIDATION_DIR = Join-Path $WORK_DIR "<PATCH_NAME>_validation"
$VALIDATOR = Join-Path $VALIDATION_DIR "validate_<PATCH_NAME>.py"

try {
    Set-Location $PROJECT_ROOT
    $env:PYTHONPATH = $PROJECT_ROOT

    if (-not (Test-Path $VALIDATION_DIR)) {
        New-Item -ItemType Directory -Path $VALIDATION_DIR -Force | Out-Null
    }

    # Write validator code to $VALIDATOR with Set-Content, then run it with Python.
    # Do not use Bash heredoc syntax in PowerShell.

    python $VALIDATOR
    if ($LASTEXITCODE -ne 0) {
        throw "validation script failed."
    }

    Write-Host ""
    Write-Host "VALIDATION OK"
    Write-Host ""
    Read-Host "Press Enter after copying this validation output"
    Read-Host "Press Enter again to clear"
    Clear-Host
}
catch {
    Write-Host ""
    Write-Host "VALIDATION FAILED:"
    Write-Host $_.Exception.Message
    Write-Host ""
    Read-Host "Press Enter after copying this validation output"
    Read-Host "Press Enter again to clear"
    Clear-Host
}
```

### 4. PowerShell compatibility rules

```text
Do not use Bash heredoc syntax such as python - <<'PY' in PowerShell.
If Python helper code is needed, write a temporary .py file under the delete-after-daily-work folder and run it.
Set $env:PYTHONPATH = $PROJECT_ROOT before importing project modules.
Validate only public files, public commands, and real generated output.
Do not validate by reading guessed or private result attributes.
```

### 5. Mandatory sandbox pre-delivery validation rule

```text
Before giving the user any ZIP, install block, or validation block, AI must test the deliverable in its own sandbox first.
AI must check at minimum: ZIP contents, expected file paths, py_compile for changed Python files, and a representative validation of the install/validation commands when possible.
AI must report sandbox validation honestly.
Local validation by the user is still required before the patch is considered complete or freezeable.
```

### 6. Runtime/cache artifact validation rule

```text
Do not classify __pycache__, .pyc, __pypackages__, .pytest_cache, .mypy_cache, .ruff_cache, or other runtime/cache folders as persistent architecture violations.
These files may be removed opportunistically, but validation must not fail merely because Python recreated them during py_compile, import, or test execution.
Persistent architecture checks should target source files, generated project memory, generated delivery artifacts, and documented box boundaries only.
```

### 7. Completion and freeze rule

```text
The process is not complete when AI gives the ZIP.
The process is not complete when install finishes.
The process is complete only after validation passes and the user pastes the clean validation output.
The patch is freezeable only after clean validation evidence.
The patch is frozen only after explicit human approval or an accepted freeze entry is installed and validated.
```
