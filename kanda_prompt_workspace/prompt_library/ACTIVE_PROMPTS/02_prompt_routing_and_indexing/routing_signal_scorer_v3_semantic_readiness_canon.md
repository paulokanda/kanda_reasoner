# Routing Signal Scorer Semantic and ML Adoption Safety Boundary

## Mission

Keep semantic, embedding, vector, provider, and ML capabilities optional, offline, and advisory unless a verified present gap proves that existing capabilities are insufficient and Brick Wall admits a bounded change.

## Core non-authority rule

Semantic or ML evidence must not decide the final route, required prompts, May proceed now, prompt loading, source mutation, freeze, or runtime authority.

## No-expansion default

Do not expand semantic or ML capability merely because a new model, vector database, provider, or roadmap sounds useful.

Before any proposal:

1. inspect exact current routing-scorer source and current freeze context;
2. inspect existing deterministic, lexical, LAB, MLRT, adviser, semantic-contract, provider-boundary, corpus, and evaluation assets;
3. identify a concrete current failure or missing capability;
4. prove existing owners cannot solve it adequately;
5. define a smallest bounded intervention and disconfirmation test.

## Required gates

### Demonstrated gap

A reproducible current deficiency with measurable impact is required.

### existing-capability review

No duplicate corpus, schema, vector manifest, provider boundary, evaluation harness, review queue, or routing engine may be created without proving the existing owner is insufficient.

### Privacy and security

Review query retention, source excerpts, private paths, sensitive Project data, external transmission, provider logs, model licensing, dependency supply chain, index poisoning, and deletion behavior.

### Provider and dependency

Local or external providers require explicit owner, disable path, resource budget, failure mode, offline fallback, version pinning, and no hidden download or network behavior.

### Runtime and persistence

Offline evidence cannot become runtime authority through a prompt change or freeze alone. Runtime or persistence changes require separate architecture scope, implementation, validation, approval, and freeze.

### Evaluation

Metrics, thresholds, latency budgets, and promotion criteria must come from current measured evidence. Do not copy placeholder numbers from historical plans.

## Existing owner references

Use the current source owners for semantic evidence contracts, provider boundaries, corpus governance, evaluation records, adviser review, and lifecycle rules. Do not reproduce their schemas here.

## Routing

Load for KANDA-specific embeddings, semantic retrieval, vector indexes, provider adoption, semantic persistence, runtime semantic authority, or audits of semantic authority leakage.

Do not load for general ML education, ordinary lexical maintenance, historical LAB explanation, or unrelated AI questions.

## Brick Wall relationship

Brick Wall must record the verified problem, current-source evidence, ownership, Box and No-Leak classification, validation obligations, and explicit authorization before implementation.
