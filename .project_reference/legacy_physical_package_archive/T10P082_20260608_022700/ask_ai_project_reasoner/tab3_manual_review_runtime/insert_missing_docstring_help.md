# Insert Missing Docstring Help

## What this workflow is for

Insert Missing Docstring helps you find Python modules, classes, functions, and methods that do not have docstrings. It lets you review each missing-docstring item, generate a draft with either the frozen heuristic generator or Local AI, and then decide what to save in the review report before any source-file writing workflow is used.

This workflow is useful when you want to document a Python project step by step without blindly inserting text everywhere. It separates scanning, draft generation, human review, report persistence, and final approval.

## Safe workflow concept

The normal flow is:

1. Open the tab named Insert Missing Docstring.
2. Choose the project root.
3. Choose what kinds of docstrings to scan.
4. Press Scan Files for Missing Docstrings.
5. Select one missing-docstring row in Review and Correct Missing Docstrings.
6. Generate a draft.
7. Read Before Correction and After Correction.
8. Save, approve, reject, undo, or continue to the next row.
9. Save or copy the report.

A scan creates or loads a report. Generate Draft creates a draft correction for the selected report row. These are separate steps.

## Project area

### Project path field

This field shows the root folder of the project that will be scanned. It should be the top-level project folder, for example:

E:\developer_tools

Use a real project root, not a subfolder unless you intentionally want to scan only that subfolder.

### Browse button

Opens a folder picker so you can choose the project root.

## Missing Docstring Handler Options

### Mode: Scan

Shows that the current workflow is scanning for missing docstrings. This mode searches for missing docstring targets and creates a reviewable report.

### Scope field

Controls how much of the project is scanned.

Typical options are project-wide scanning or a narrower target path. Use a narrow scope when testing.

### Target path field

Lets you restrict the scan to a specific file, module, package, or folder depending on the selected scope.

### Browse target button

Lets you pick a target path for a narrower scan.

### Clear target button

Clears the target path so the scan returns to the broader selected scope.

### Module Header Docstring checkbox

When checked, the scan includes missing module-level docstrings. A module docstring is the top docstring of a Python file.

### Classes checkbox

When checked, the scan includes classes without class docstrings.

### Function/Method checkbox

When checked, the scan includes functions and methods without docstrings.

### Path Module at top of file checkbox

When checked, the workflow can include a managed file path header at the top of the file. Use this only when you want the project to keep managed path comments. Leave it unchecked if you only want docstrings.

### Workers field

Sets how many workers the scan can use. More workers can scan faster, but use a moderate value if you want safer behavior on a large project.

### Scan Files for Missing Docstrings button

Runs the scan. This button finds missing-docstring targets and creates or loads the report. It does not mean Generate Draft.

When pressed, the workflow may ask whether to use a previously saved report or run a fresh scan. If you run a fresh scan, it may ask what to do with older reports and where to save the new report.

### Stop Running button

Requests cancellation of the active scan or long-running operation.

### Help button

Opens this help file.

## Local AI area

Local AI controls whether drafts are generated by an OpenAI-compatible local model or by the frozen heuristic generator.

### Enable Local AI checkbox

When checked, Generate Draft uses the Local AI provider. If the provider fails, the workflow can fall back to the frozen heuristic draft.

When unchecked, Generate Draft uses the frozen heuristic generator only.

### Base URL field

The OpenAI-compatible local endpoint. For Ollama-style OpenAI compatibility, a common value is:

http://localhost:11434/v1

The provider posts to the chat completions endpoint derived from this URL.

### Model field

The model name used by the Local AI provider. Choose an installed model from the list or the configured model entry.

### Refresh button

Refreshes the available model list when supported.

### Config path field

Path to a configuration file used by the Local AI settings.

### Config Load button

Loads Local AI configuration from the config path.

### Config Save button

Saves the current Local AI configuration to the config path.

### Include private checkbox

Controls whether private symbols should be included when building context for AI generation. Use carefully because private names may be implementation details.

### Minimum confidence field

Controls the minimum accepted confidence policy for AI output when that policy is used. This is not the same as AI draft style. It is a safety/acceptance setting, not a verbosity setting.

### No uncertain checkbox

When checked, uncertain AI results should be avoided or rejected when the policy supports it.

### AI draft style field

Controls AI draft verbosity.

- Concise: short draft. Usually one sentence or brief NumPy-style sections only when needed.
- Balanced: moderate draft. Adds small useful detail when source context supports it.
- Detailed: longer draft. Allows a short explanation and fuller parameter or return descriptions when source context supports it.

The AI draft style is read when you press Generate Draft, Generate Visible Drafts, or Generate All Drafts. Changing the style alone does not automatically regenerate the selected row. Press Generate Draft again after changing the style.

## Output area

Shows scan output, provider messages, errors, status updates, and diagnostic trace lines.

Useful diagnostic lines may start with:

[review-style-trace]

These lines help confirm which AI draft style was read, what was stored in the row, and what the preview used.

## Report area

### Report path field

Shows where the current report is loaded from or saved to. Reports are usually JSONL files.

### Browse report button

Lets you choose the report file path.

### Save report button

Saves the current report state, including review decisions and stored draft fields.

### Load report button

Loads an existing report.

### Copy report button

Copies the report content for use elsewhere.

## Review and Correct Missing Docstrings area

This area is where you inspect missing-docstring rows and decide what to do with each draft.

## Before Correction area

### Summary

Shows summary information for the selected row.

### Filter field

Filters the review list. Use it to show all rows, pending rows, approved rows, rejected rows, or other supported review states.

### Previous button

Moves to the previous review row.

### Next button

Moves to the next review row.

### Reset button

Resets the current navigation or selected row display, depending on the current review state.

### Review list

Shows missing-docstring rows found by scan or loaded from a report. Select a row before generating a draft.

### Original snippet

Shows the source snippet before correction. This is read-only.

## After Correction area

### Correction status label

Shows which engine is active:

- HEURISTIC CORRECTION: Local AI is disabled.
- CORRECTION WITH AI: Local AI is enabled.

### Draft status label

Shows whether a draft exists and where it came from:

- NO DRAFT GENERATED
- HEURISTIC DRAFT GENERATED
- AI DRAFT GENERATED
- AI UNAVAILABLE - HEURISTIC FALLBACK

### Generate Draft button

Generates a draft only for the selected row.

Use this button after selecting a row and choosing AI or heuristic settings. This is the main button for testing Concise, Balanced, and Detailed AI styles on one row.

### Generate Visible Drafts button

Generates drafts for rows currently visible under the active filter.

### Generate All Drafts button

Generates drafts for all reviewable rows. This may take longer and should ask for confirmation.

### Undo Last Bulk Drafts button

Restores the draft fields that existed before the last bulk draft generation.

### Save Review Decision button

Saves the visible generated draft decision for the selected row. It does not secretly generate a new draft. If no draft exists, use Generate Draft first.

### Approve Row button

Marks the selected row as approved using the current visible/generated draft.

### Reject Row button

Marks the selected row as rejected.

### Undo Row Change button

Reverts the last review decision or row-level draft change when supported.

### Approve Visible Rows button

Approves rows currently visible under the active filter. Use only after you have reviewed the visible rows carefully.

### Corrected snippet

Shows how the selected snippet would look after the generated draft is applied. This is the preview area. It is read-only.

## Complete heuristic example

1. Open the tab named Insert Missing Docstring.
2. In Project, choose the project root.
3. In Missing Docstring Handler Options, choose the scan scope.
4. Check Module Header Docstring, Classes, or Function/Method depending on what you want to find.
5. Leave Enable Local AI unchecked.
6. Press Scan Files for Missing Docstrings.
7. Select a row in Review and Correct Missing Docstrings.
8. Confirm the status shows HEURISTIC CORRECTION.
9. Press Generate Draft.
10. Read Before Correction and After Correction.
11. If the draft is acceptable, press Save Review Decision or Approve Row.
12. Continue with Next.
13. Save report when done.

## Complete Local AI example for one selected row

1. Open the tab named Insert Missing Docstring.
2. In Project, choose the project root.
3. In Missing Docstring Handler Options, choose the scan scope.
4. Check the target types to scan: Module Header Docstring, Classes, Function/Method, or Path Module at top of file.
5. Press Scan Files for Missing Docstrings.
6. In Local AI, check Enable Local AI.
7. Set Base URL, for example http://localhost:11434/v1.
8. Choose the Model.
9. Press Refresh if the model list needs updating.
10. Set Config path if you want to load or save Local AI settings.
11. Set Minimum confidence and No uncertain according to your safety preference.
12. Select AI draft style: Concise, Balanced, or Detailed.
13. Select one row in Review and Correct Missing Docstrings.
14. Press Generate Draft.
15. Read the Output panel for provider status or fallback messages.
16. Read the Corrected snippet.
17. If you change AI draft style, press Generate Draft again. Changing style alone does not regenerate.
18. Press Save Review Decision or Approve Row only after checking the draft.
19. Save report when done.

## Complete Local AI bulk example

1. Open the tab named Insert Missing Docstring.
2. Choose the project root.
3. Run Scan Files for Missing Docstrings or Load report.
4. Enable Local AI.
5. Set Base URL and Model.
6. Select AI draft style.
7. Use Filter to decide which rows are visible.
8. Press Generate Visible Drafts to generate drafts only for visible rows.
9. Or press Generate All Drafts to generate drafts for all reviewable rows.
10. Read the confirmation dialog before Generate All Drafts.
11. Review the generated drafts.
12. If the bulk draft is not acceptable, press Undo Last Bulk Drafts.
13. Save report when done.

## Common mistakes

### Mistake: pressing Scan again when you meant to generate a draft

Scan Files for Missing Docstrings finds missing docstrings and builds the report. Generate Draft creates a draft correction for a selected row.

### Mistake: changing AI draft style but not pressing Generate Draft again

The style is used when a draft is generated. After changing Concise, Balanced, or Detailed, press Generate Draft again for the selected row.

### Mistake: reviewing an old cached draft

If a report was loaded from disk, it may already contain draft fields. Press Generate Draft again to create a fresh draft with the current Local AI and style settings.

### Mistake: assuming Minimum confidence controls length

Minimum confidence is a safety/acceptance setting. AI draft style controls length and detail.

### Mistake: assuming Local AI writes directly to source files

Local AI creates review drafts. Human review is still required. Source-file writing should remain controlled by the existing review/apply workflow.

## Recommended safe testing sequence

1. Use a small fake project first.
2. Run scan with only Function/Method checked.
3. Select one row.
4. Test Concise, Balanced, and Detailed using Generate Draft.
5. Review Output trace lines.
6. Save the report.
7. Reload the report and confirm drafts persist.
8. Only then use larger scopes or bulk generation.
