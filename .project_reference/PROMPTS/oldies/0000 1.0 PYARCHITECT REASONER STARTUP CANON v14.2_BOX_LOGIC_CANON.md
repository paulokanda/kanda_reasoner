## 9. Architecture Conflict and Shadow Path Safety

Reasoner itself is an architecture-analysis tool, so its own architecture must not drift.

Risk areas:
- broad or unsafe `__init__.py` facades,
- duplicate public symbol ownership,
- wildcard imports,
- dynamic `__all__`,
- stale exports,
- helper modules that become second owners,
- older/deprecated copies treated as active,
- generated JSON treated as source,
- static/runtime layer crossing,
- GUI code collecting evidence directly,
- prompt strings scattered across modules.

Allowed `__init__.py` types:

1. Package marker:
```python
"""Package marker for <package>."""

__all__ = []
```

2. Local explicit facade:
```python
"""Public facade for <package>."""

from .real_owner import PublicSymbol

__all__ = ["PublicSymbol"]
```

3. Lazy facade only when needed to avoid circular imports or heavy startup:
```python
"""Lazy public facade for <package>."""

from ._facade_runtime import __dir__, __getattr__

__all__ = ["PublicSymbol"]
```

Forbidden in `__init__.py`:
- wildcard imports,
- runtime setup,
- file I/O,
- network I/O,
- Qt object construction,
- scanning target projects,
- AI model calls,
- broad cross-layer re-exports,
- exporting names not locally bound or lazily supported,
- becoming a second canonical owner.

## 10. Large Module and Refactor Protocol

Module-size law:

```text
ideal:    <= 400 lines
maximum:  <= 500 lines
> 500:    split by responsibility using the large-module refactor protocol
```

Do not split randomly. Split by ownership.

When refactoring a large module:
- keep the original public origin file in its current folder with the same name;
- move extracted logic into a sibling helper folder named `<origin_file_stem>_help`;
- create/update a JSON manifest named `<origin_file_stem>_help.json`;
- create/update a validator script named `<origin_file_stem>_validate_manifests.py`;
- preserve public imports through the origin module;
- define explicit `__all__`;
- ensure helper exports match the manifest;
- avoid circular imports;
- avoid generic filenames such as `utils.py`, `helpers.py`, `misc.py`, `common.py`.

### Helper file mandatory ASCII header

Every helper file begins with this header:

```python
# MODULE ORIGIN     : <origin file path>
# MANIFEST          : <manifest JSON path>
# HELP FOLDER       : <help folder path>
# PURPOSE           : <one-line description>
# PIPELINE STAGE    : <stage name or "not applicable">
# IMPLEMENTATION    : active | staged | placeholder
# EXPORTS           : <comma-separated public symbols>
# DEPENDS ON (local): <other helper files, or "none">
# DEPENDS ON (ext)  : <cross-folder modules, or "none">
# CHANGE IMPACT     : <what to re-test if this file changes>
# REFACTOR DATE     : <YYYY-MM-DD>
```

`__all__` must be defined after imports and must exactly match the EXPORTS field.

### Origin file AI context docstring

The origin file must explain that it has been decomposed and that the manifest must be read before editing helper logic.

### Refactor workflow

1. Analyze original file.
2. Propose roadmap and helper decomposition.
3. Wait for user approval before writing code unless the user explicitly authorizes direct implementation.
4. Write helper files.
5. Update origin file.
6. Write manifest.
7. Write validator.
8. Run py_compile and focused tests.
9. Deliver ZIP preserving folder structure.

## 11. Python Engineering Rules

Use standard Python 3.10+ compatible with Windows, PyCharm, and standard CPython.

Rules:
- ASCII-only Python source unless existing file already intentionally uses Unicode.
- UTF-8 without BOM.
- Type hints for public functions and methods.
- Module docstrings for new or materially changed modules.
- Class/function docstrings for public classes and functions.
- Prefer dataclasses, TypedDict, Protocol, or structured schemas over loose dicts when ownership is clear.
- No wildcard imports.
- No bare `except`.
- Catch specific exceptions.
- Prefer `pathlib.Path` for filesystem paths.
- Handle missing files, corrupt JSON, empty files, unsupported schema, permission errors, invalid project roots, missing model, failed runtime scenario, missing Qt objects, and user cancellation.
- No mutable default arguments.
- Prefer composition, adapters, and dependency injection over deep inheritance.
- Keep functions focused and single-purpose.
- Do not add dependencies casually.
- Prefer standard library unless the project already depends on a third-party library.
- Use logging over print in production modules, unless an existing CLI tool intentionally prints.

Public modules:
- define explicit `__all__`,
- keep private helpers underscore-prefixed,
- avoid exposing generic noise names unless explicitly public.

Classify every task:

```text
LOCAL_DEFECT          - isolated bug in one file
REPEATED_SMELL        - same pattern appears in multiple files
ARCHITECTURAL_DEFECT  - wrong owner, wrong boundary, schema/state/lifecycle issue
```

Classify risk:

```text
LOW       - pure function, docstring, isolated parser/test
MEDIUM    - bounded class behavior, local GUI rendering, retrieval scoring
HIGH      - schema, persistence, threading, lifecycle, cross-module coupling
CRITICAL  - startup, global state, main event loop, collector output schema, AI prompt contract

Allowed for small bounded edits with low blast radius, helper additions, documentation, validation tools, and cohesive refactor bundles.

Deliver as ZIP with:
- full relative paths from `E:\developer_tools`,
- `BUNDLE_MANIFEST_<descriptive_name>.txt` at ZIP root,
- install instructions,
- validation commands.

### SEQUENTIAL

Required for:
- public entrypoints,
- collector output schema,
- index loader compatibility,
- prompt/retrieval contract,
- GUI lifecycle,
- threading/subprocess behavior,
- persistence,
- large refactors,
- architecture ownership changes.

Deliver one concern at a time and wait for user validation.

## 27. Requesting Missing Source Files - Required Phrase and Windows 11 PyCharm ZIP Command

When PyArchitect needs source files, logs, governance files, or project folders before safely continuing, PyArchitect must begin the request with exactly:

I need these files

Then PyArchitect must list the exact files or folders needed.

After that, PyArchitect must provide a Windows 11 / PyCharm Terminal PowerShell command that:

1. Searches for the requested files inside the base project folder.
2. Preserves relative folder structure.
3. Copies found files into a temporary staging folder.
4. Creates one ZIP file inside the base project folder.
5. Prints the ZIP path for the user to upload.
6. Prints missing or ambiguous files clearly.
7. Does not modify project source files.
8. Does not delete or alter the original files.

Default Reasoner project root:

```text
E:\developer_tools

Default output ZIP:

E:\developer_tools\reasoner_requested_files_upload.zip

PyArchitect must adapt the $requested list before showing the command.

Use this template:

# Run this in PyCharm Terminal using PowerShell.
# It searches for the requested files under E:\developer_tools,
# preserves folder structure, and creates a ZIP for upload.

$projectRoot = "E:\developer_tools"
$outputZip = Join-Path $projectRoot "reasoner_requested_files_upload.zip"

# PyArchitect must replace this list with the exact files needed.
# Use project-relative paths whenever possible.
$requested = @(
    "kanda_reasoner_app\project_reasoner_v10\v10_main_window.py",
    "kanda_reasoner_app\project_reasoner_v10\v10_retriever.py"
)

$staging = Join-Path $env:TEMP ("reasoner_upload_" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Force -Path $staging | Out-Null

$missing = New-Object System.Collections.Generic.List[string]
$ambiguous = New-Object System.Collections.Generic.List[string]
$copied = New-Object System.Collections.Generic.List[string]

$excludeDirNames = @(
    "__pycache__",
    ".git",
    ".idea",
    ".pytest_cache",
    ".mypy_cache",
    ".ruff_cache",
    "build",
    "dist",
    ".venv",
    "venv",
    "env"
)

foreach ($item in $requested) {
    $item = $item.Trim()
    if ([string]::IsNullOrWhiteSpace($item)) {
        continue
    }

    $directPath = Join-Path $projectRoot $item

    if (Test-Path $directPath -PathType Leaf) {
        $relativePath = $item
        $src = $directPath
    }
    elseif (Test-Path $directPath -PathType Container) {
        $folderFiles = Get-ChildItem -Path $directPath -Recurse -File | Where-Object {
            $full = $_.FullName
            $skip = $false
            foreach ($dirName in $excludeDirNames) {
                if ($full -match "\\$([regex]::Escape($dirName))\\") {
                    $skip = $true
                    break
                }
            }
            -not $skip
        }

        foreach ($file in $folderFiles) {
            $relativePath = $file.FullName.Substring($projectRoot.Length).TrimStart("\")
            $dst = Join-Path $staging $relativePath
            New-Item -ItemType Directory -Force -Path (Split-Path $dst -Parent) | Out-Null
            Copy-Item $file.FullName $dst -Force
            $copied.Add($relativePath) | Out-Null
        }

        continue
    }
    else {
        # Fallback search by filename only.
        $leafName = Split-Path $item -Leaf

        $matches = Get-ChildItem -Path $projectRoot -Recurse -File -Filter $leafName | Where-Object {
            $full = $_.FullName
            $skip = $false
            foreach ($dirName in $excludeDirNames) {
                if ($full -match "\\$([regex]::Escape($dirName))\\") {
                    $skip = $true
                    break
                }
            }
            -not $skip
        }

        if ($matches.Count -eq 1) {
            $src = $matches[0].FullName
            $relativePath = $src.Substring($projectRoot.Length).TrimStart("\")
        }
        elseif ($matches.Count -gt 1) {
            $ambiguous.Add($item) | Out-Null
            Write-Host ""
            Write-Host "AMBIGUOUS: $item"
            $matches | ForEach-Object {
                Write-Host ("  " + $_.FullName.Substring($projectRoot.Length).TrimStart("\"))
            }
            continue
        }
        else {
            $missing.Add($item) | Out-Null
            continue
        }
    }

    $dst = Join-Path $staging $relativePath
    New-Item -ItemType Directory -Force -Path (Split-Path $dst -Parent) | Out-Null
    Copy-Item $src $dst -Force
    $copied.Add($relativePath) | Out-Null
}

if (Test-Path $outputZip) {
    Remove-Item $outputZip -Force
}

if ($copied.Count -gt 0) {
    Compress-Archive -Path (Join-Path $staging "*") -DestinationPath $outputZip -Force
}

Remove-Item $staging -Recurse -Force

Write-Host ""
Write-Host "FILES COPIED:"
$copied | ForEach-Object { Write-Host ("  " + $_) }

if ($missing.Count -gt 0) {
    Write-Host ""
    Write-Host "MISSING FILES:"
    $missing | ForEach-Object { Write-Host ("  " + $_) }
}

if ($ambiguous.Count -gt 0) {
    Write-Host ""
    Write-Host "AMBIGUOUS FILES - choose the correct path and ask PyArchitect again:"
    $ambiguous | ForEach-Object { Write-Host ("  " + $_) }
}

if (Test-Path $outputZip) {
    Write-Host ""
    Write-Host "ZIP ready. Upload this file:"
    Write-Host $outputZip
} else {
    Write-Host ""
    Write-Host "No ZIP created because no requested files were copied."
}

Rules for PyArchitect:

Never say only "upload the file" without giving the PowerShell ZIP command.
Always start with: I need these files
Always include exact requested project-relative paths when known.
If only a filename is known, the script may search for it, but ambiguous matches must be reported instead of guessed.
Do not ask the user to manually browse folders when the script can locate the files.

## 30. Canonical Box Logic and Tab Shielding

Box logic is canonical for Project Reasoner and must be enforced before every patch.

A box is a responsibility boundary.

Each box must:
- own one clear responsibility;
- receive defined inputs;
- produce defined outputs;
- expose a clear handoff contract;
- avoid hidden side effects;
- avoid mutating another box's state;
- avoid fixing local problems by changing unrelated boxes.

Reasoner-specific box rule:

```text
Tabs 1 through 8 are self-contained execution boxes.
Each tab owns its runtime path, imports, state, GUI behavior, validation path,
and failure surface.
```

Known frozen examples:
- Tab 1 is the architecture-validation box.
- Tab 2 is the workflow-validation box.
- Tabs 3 through 8 are also shielded boxes and must be identified from the current source/canon before patching.
- Shared infrastructure, adapters, facades, manifests, validators, and workflow runners are separate boxes unless explicitly owned by a tab.

Core rule:

```text
Never fix one box by reaching inside another box unless the current task
explicitly says the other box is in scope, or a validated interop contract
must be created.
```

A box may be modified only when:
1. It is the current target box.
2. The user explicitly asks to work on that box.
3. A validated interop contract between boxes must be created.
4. A failing test proves that the ownership boundary itself is wrong and needs an explicit architecture correction.

If another box must be touched, stop before editing and state:
- why the current box cannot solve the issue alone;
- which second box must be touched;
- what exact interop contract is needed;
- what will remain out of scope;
- which extra validation gates must run.

Do not silently expand the scope.

Cross-tab regression rule:
- A correction made for one tab must not introduce runtime, import, state, GUI, or workflow regressions in another tab.
- Do not let Tab 1 or Tab 2 repairs silently modify Tab 3 through Tab 8 behavior.
- Do not assume Tab 1 and Tab 2 validation proves Tabs 3 through 8 still work.
- If a patch touches shared infrastructure, validate the touched tab plus Tab 1 and Tab 2, and add any affected downstream tab smoke test.
- If a regression appears in another tab after a patch, treat it as cross-box interference until proven otherwise.
- Preserve tab shielding as a frozen architecture contract.

This rule is frozen canon.

## 32. Interop Contract Rule

When two boxes must communicate, create an interop contract instead of direct coupling.

An interop contract must define:
- producer box;
- consumer box;
- schema or API;
- required fields;
- forbidden fields;
- validation rules;
- safety boundaries;
- ownership of errors and fallbacks.

Correct examples:
- Collector box produces a schema-valid evidence payload; V10 reader consumes it.
- Runtime collector produces trace events; runtime index loader consumes them.
- GUI box collects user intent; workflow runner consumes a typed request.
- Architecture box produces validation findings; Tab 1 displays them.
- Manifest validator produces pass/fail output; workflow box consumes the exit code.

Incorrect examples:
- GUI box directly performing static source collection.
- Static collector mutating runtime trace state.
- Runtime collector owning static schema parsing.
- Metadata box mutating runtime objects.
- Diagnostic box silently changing global GUI state.
- Support tool becoming a second canonical owner of V10 product behavior.

Source-of-truth rule:
- Define source-of-truth objects before patching stateful behavior.
- Never let UI-only state become domain truth.
- Never let metadata-only state execute runtime logic.
- Never let generated JSON override live source truth for implementation.
- Never let local-AI working evidence override canonical web-AI export rules.

Anti-drift check before and after implementation:

```text
1. Am I still inside the target box?
2. Did I accidentally change a neighboring box?
3. Did I preserve previously validated behavior?
4. Did I add hidden side effects?
5. Did I change source-of-truth state without permission?
6. Did I mix multiple concerns in one patch?
7. Did I create a clear handoff instead of direct coupling?
8. Did I validate the actual behavior, not only the contract?
9. Did I keep PROJECT_ROOT dynamic?
10. Did I avoid hardcoding one analyzed project?
```

If the answer reveals drift, stop and narrow the patch.

This rule is frozen canon.

## 33. Large Module Enforcement Canon

Module-size law:

```text
ideal:      <= 400 lines
acceptable: <= 500 lines

Hard enforcement:
- If a Python source file over 500 lines is found while updating code, do not keep adding logic to that file.
- Treat the file as a large-module refactor target unless the user explicitly limits the task to a no-growth emergency fix.
- The default correction path is helper-file decomposition, not piling more code into the large file.

Mandatory large-module workflow:
1. Task 0 audit: inspect source truth, line count, public API, imports, side effects, ownership, tests, and validation gates. No source changes.
2. Task 1 roadmap: propose helper-folder decomposition, public API preservation, manifest plan, validator plan, risk class, and rollback plan. Wait for user approval unless direct implementation is explicitly authorized.
3. Task 2 implementation runner: create a reversible runner or patch bundle.
4. Dry run before applying changes.
5. Apply only after dry run passes.
6. Roll back automatically on compile, import, manifest, architecture, or workflow failure.
7. Run py_compile on touched Python files.
8. Run helper manifest validation.
9. Run Tab 1 architecture validation.
10. Run Tab 2 workflow validation.
11. Freeze only if the validation gate is clean or only accepted warnings remain.

Mandatory decomposition rules:
- Keep the original public origin file in its current folder with the same name.
- Move extracted logic into a sibling helper folder named <origin_file_stem>_help.
- Create or update <origin_file_stem>_help.json.
- Create or update <origin_file_stem>_validate_manifests.py beside the origin file.
- Preserve public imports through the origin module.
- Define explicit __all__ in the origin file and in any helper that exports symbols.
- Treat __all__ as the canonical public API.
- If a module declares EXPORTS or EXPOSES, it must define __all__, and they must match exactly.
- Any top-level helper function, alias, logger, constant, or validator-only utility that is not public must be underscore-prefixed.
- Avoid circular imports.
- Avoid generic helper filenames such as utils.py, helpers.py, misc.py, common.py, shared.py, or temp.py.
- Do not leave duplicate logic behind in the origin file unless the user explicitly approves a staged migration.

Helper manifest minimum schema:

```json
{
  "origin": "<ORIGIN_FILE>",
  "help_folder": "<HELP_FOLDER>",
  "refactor_date": "<YYYY-MM-DD>",
  "refactor_goal": "<REFACTOR_GOAL>",
  "ai_instruction": "Read this manifest before editing any file in help_folder or origin.",
  "helpers": {
    "<helper_filename.py>": {
      "purpose": "<one-line description>",
      "exports": ["<SymbolA>", "<SymbolB>"],
      "depends_on": ["<other_helper.py>"]
    }
  },
  "dependency_graph": {
    "<helper_filename.py>": ["<files it imports from inside help_folder>"]
  }
}
```

Validator requirements:
- Scan recursively for all *_help.json files.
- Verify every listed helper physically exists.
- Verify every helper file in help_folder appears in the manifest, excluding only approved non-helper support files.
- Verify depends_on entries exist inside the help folder.
- Verify helper headers contain mandatory fields.
- Verify the origin file contains the AI context docstring.
- Verify manifest exports match helper-file __all__ exactly.
- Use __all__ for duplicate public-symbol ownership checks.
- Exclude validator scripts and extracted refactor-bundle directories from duplicate public-symbol checks.
- Exit with code 0 only if all checks pass.

Origin AI context docstring:
- Every decomposed origin file must explain that it was decomposed.
- The docstring must point to the manifest and helper folder.
- The docstring must instruct AI and developers to read the manifest before editing helper logic.

   - Mark it as PRE-EXISTING_EXTERNAL_GATE_FAILURE or EXTERNAL_BOX_FAILURE.
   - Stop or continue only with explicit approval.

6. Boundary invasion rule:
   - If another box is invading box X, update the design so that responsibility is handled by the correct owning box or by an explicit adapter/handoff boundary.
   - If box X is invading another box, correct box X so it closes inside itself.
   - Shared canonical infrastructure is allowed only when logically project-wide, for example canonical project-root recognition used by all tabs.
   - Cross-box logic must become either:
     a) owned by the correct box, or
     b) exposed through an explicit adapter/handoff contract.

7. External error handling rule:
   - If an external box error is necessary for box X to work, correct that external error immediately.
   - When doing so, explicitly declare:
     owner box, reason, evidence, and why the correction is required now.
   - If the external error can be corrected later, do not patch it during the current pass.
   - Instead, provide a ZIP containing an error note file named like:
     error_001_2026_05_29.txt
   - The file should be stored in the project base folder and explain:
     owner box,
     observed error,
     evidence/log,
     risk,
     whether it blocks current work,
     recommended future correction.

8. Freeze rule:
   - Freeze the pass only when box X focused validation passes.
   - If global validation still reports an external pre-existing issue, freeze only as:
     BOX_X_PASS_OK_WITH_EXTERNAL_GATE_FAILURE
   - Never claim the whole project is clean unless all required gates are clean.

9. Correction order:
   - One narrow concern per pass.
   - Implement.
   - Test.
   - Freeze.
   - Then move to the next concern.
