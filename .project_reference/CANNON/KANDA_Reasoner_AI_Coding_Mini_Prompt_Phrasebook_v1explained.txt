KANDA REASONER AI CODING MINI-PROMPT PHRASEBOOK v2 - EXPLAINED EDITION

Purpose
Use these phrases while programming with AI and KANDA Reasoner. They are generalized for any Active Project selected in the reusable KANDA Reasoner Tool.

How to use the explanations
Each mini-prompt is followed by a plain-English explanation for a non-programmer vibe-coding user. The explanation tells you what the command makes the AI do, when to use it, and which common AI mistake it is designed to prevent.

Core identity
- KANDA Reasoner Tool = reusable engineering tool.
- Active Project = selected source and durable-result owner.
- Tool and Project remain logically separate even when both point to the same physical root during self-hosting.
- Brick Wall is the final coding and release authority coordinator.
- Specialist prompts remain authoritative for their own domains.

Placeholders
<active_project> = currently selected Project
<active_project_root> = current Project source root
<active_project_support_root> = current sibling support root
<target> = module, feature, workflow, prompt, or artifact being changed
<primary_box> = Box that owns the main responsibility
<public_facade> = supported public contract of the owning Box
<feature_id> = current immutable feature or repair identity
<operation_id> = current operation identity
<validation_marker> = exact expected validation marker

A. UNIVERSAL PREFIXES
======================================================================

A1. Full universal implementation prefix
Treat KANDA Reasoner as the reusable Tool and <active_project> as the Active Project. Preserve Tool-versus-Project separation even during self-hosting. Route this task through the current prompt indexes, load only the smallest applicable specialist prompt set, apply Box Architecture and NO_LEAK logic, and use Brick Wall as the final coding authority. Inspect exact current source before proposing code. Prefer the smallest verified intervention, preserve public contracts and single-state ownership, validate from current source, and do not claim installation, validation, Freeze, or Error Memory completion without observed evidence.
A1. Explanation (plain English for a non-programmer user): This command gives the AI the complete KANDA operating frame before implementation. It identifies the Tool and selected Project, requires prompt routing, Box and NO_LEAK protection, Brick Wall authority, exact-source inspection, minimal change, and truthful evidence reporting. Use it at the beginning of an important implementation or when the AI has forgotten several project rules at once.

A2. Short universal guard
Respect Tool/Project boundaries, Box ownership, public-contract-only communication, NO_LEAK logic, current exact source, and Brick Wall authorization. Make the smallest bounded change and preserve all unrelated behavior.
A2. Explanation (plain English for a non-programmer user): This is the compact version of the universal guard. It reminds the AI to respect the Tool/Project split, ownership, public interfaces, no-leak rules, live source, and final authorization while changing as little as possible. Use it during an ongoing task when the full A1 prompt would be excessive.

A3. Surgical repair prefix
This is a surgical repair of <target>. Identify the verified defect, its canonical owner, public contract, consumers, and regression risk. Change only the smallest authorized file set inside the owning Box. Keep unrelated corrected behavior shielded and unchanged.
A3. Explanation (plain English for a non-programmer user): This command tells the AI to repair one verified problem without redesigning the surrounding system. It must find the real defect, the feature that owns it, the approved interface used by other code, and the regression risk, then touch only the smallest allowed set of files. Use it when you want a precise repair or when the AI is rewriting too much unrelated code.

A4. Read-only audit prefix
Audit only. Inspect current Project source and relevant KANDA prompts, but do not modify source, generate an installable patch, write Project memory, or claim validation. Separate findings, evidence, assumptions, and unresolved questions.
A4. Explanation (plain English for a non-programmer user): This command puts the AI into inspection-only mode. It may read and report, but it must not edit source, build a patch, write memory, or pretend that validation occurred. Use it when you want diagnosis, architecture review, or a second opinion before approving implementation.

A5. Quality-over-growth prefix
Do not create a new engine, scanner, registry, schema, report owner, or context system merely because it sounds useful. First prove a concrete inadequacy in the current canonical capability. Prefer repair, consolidation, or no change.
A5. Explanation (plain English for a non-programmer user): This command prevents feature inflation. It requires proof that the existing system is genuinely inadequate before creating another engine, scanner, registry, schema, or report owner. Use it when the AI keeps proposing new infrastructure instead of improving what already exists.
